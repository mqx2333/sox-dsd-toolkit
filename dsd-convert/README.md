# PCM ↔ DSD 指令生成器（合并版）

一个 GUI，双向转换，**方向按源文件扩展名自动判定**，只显示该方向相关的控件。

```
PCM (.flac/.wav/.aiff/… )  ──to-dsd──▶  DSD (.dsf/.dff)
DSD (.dsf/.dff/.wsd)       ──to-pcm──▶  PCM (.wav/.flac)
```

原来两个独立程序（`dsd-converter` PCM→DSD、`dsd-to-pcm` DSD→PCM）已合并到这里，
两者归档在 `_legacy/`。

---

## 运行

```powershell
# 双击
run.bat

# 或
python gui.py
```

无第三方依赖，只需 Python 3.8+ 自带 tkinter。

---

## 界面

选好源文件后，方向、面板、输出名、目标速率全部自动就位，并立刻测量源文件：

| 源 | 判定 | 显示的设置面板 |
|---|---|---|
| `.flac` / `.wav` / `.aiff` … | PCM → DSD | 增益、DSD 速率、噪声整形滤波器、trellis |
| `.dsf` / `.dff` | DSD → PCM | 位深、目标采样率、容器 |

底部四个按钮：**一键复制指令**、**重新生成**、**测量源文件**、
**直接执行转换（带进度条）**、**验证产出**。

## PCM → DSD 的规则（实测依据）

**① 增益由实测峰值算出**

```
gain = -6.0 dBFS − 实测峰值
```

因为 sox 的 `sdm` 内部把输入乘 0.5（`src/sdm.c`），**PCM 0 dBFS 等于调制器满幅**，
而其稳定上限约 ±0.71（= +3.1 dBDSD，SACD 峰值上限）。峰值顶格的母带直入必然过载，
而 PCM 域的 `Clip:0` 看不出来。界面左上会显示算式来源。

**② 必须显式给 `-f`**：不指定时 `sdm_find_filter(NULL, rate)` 返回最低阶的 `clans-4`，
不报错但带内噪声明显变差。

**③ trellis 默认关闭**：需给 `-t/-n/-l` 才启用（order 3–32 / paths 4–32 / latency 100–2048）。

生成的指令形态：

```powershell
sox_ng.exe "in.flac" -t dsf "out.dsf" gain -6 rate -v 2822400 sdm -f sdm-6 -t 8 -n 16 -l 512
```

## DSD → PCM 的规则（实测依据）

**① 输出速率是必需的**：sox_ng 的读取器按设计只把 1-bit 展开成 ±满幅样本、速率标为 DSD 速率，
PCM 转换交给普通 `rate` 重采样器；SoX **只在输出速率与输入速率不同时**才自动插入 `rate`。
不给速率就会把 1-bit 流当 8-bit PCM 原样写出（±1.0 方波、峰值 0.00 dBFS）。

**② 位深必须 24-bit**：实测 16-bit 让 DSD64/128/256 的带内噪声底劣化
**13.6 / 17.9 / 22.3 dB**。

**③ 目标速率取 2× 基率**（DSD64→88.2k、DSD128→176.4k、DSD256→352.8k；48k 家族→96/192/384k）。
理由不是噪声底——24-bit 下目标速率对它影响很小（DSD64 在 44.1k–176.4k 间只差 2.6 dB）——
而是**给重建滤镜留过渡带**：DSD64 转 44.1k 时 20 kHz 距 Nyquist 只剩 2 kHz。

**④ 按能力路由解码器**：

| 源 | 解码器 | 原因 |
|---|---|---|
| DSF、非压缩 DFF | **sox_ng** | 能读 |
| **DST 压缩的 DFF** | **ffmpeg** | sox_ng 报 `unsupported compression` |

两个解码器实测**等价**：六音探针（100 Hz–18 kHz）每个音差 **0.00 dB**，
逐频段光谱差 < 1 dB，全带宽 RMS −85.72 vs −85.67 dBFS。

生成的指令形态：

```powershell
# sox_ng 路径
sox_ng.exe "in.dsf" -t wav -e signed-integer -b 24 "out.wav" rate -v 88200
# DST 路径
ffmpeg.exe -hide_banner -loglevel warning -y -i "in.dff" -c:a pcm_s24le -ar 176400 "out.wav"
```

## 关于 DSD 的码率（常见误解）

有人会算：DSD64 每声道 2822.4 kbps，而 88.2k/24-bit PCM 只有 2116.8 kbps，装不下。
**这个比较不成立**，因为 DSD 的位率不能和 PCM 的位率直接比：

- **DSD 的位高度相关**。静音时 DSD64 的字节熵只有 **3.90/8 bit（48.8%）**，
  位转移率 0.735 —— 位率的一大半是冗余。PCM 的位是独立符号。
- **DSD 位率里绝大部分是超声噪声**。把同一段正弦以不同电平编码成 DSD64 再解回原生 2.8224 MHz：

  | 信号电平 | 带内(20 Hz–20 kHz) | 带外(>20 kHz) |
  |---|---|---|
  | 0 dBFS | 99.35% | 0.655% |
  | −6 dBFS | 97.73% | 2.27% |
  | **−20 dBFS** | **63.4%** | **36.6%** |
  | −60 dBFS | 0.017% | **99.98%** |

  调制器的量化噪声总量固定、不随信号电平变化，所以信号越轻，位率里噪声占比越高。
- **信息论上也够**：20 Hz–20 kHz 的内容按 Nyquist 只需 >40 kHz 采样率，88.2 kHz 有 2 倍余量；
  24-bit 提供约 146 dB 动态范围，而 DSD64 实测带内噪声底约 −116 dB。

**DSD64 被丢弃的是 20 kHz 以上的超声噪声**，那正是噪声整形刻意推出去的东西，不是信号。
所以如果源是 DSD128，就该用 176.4 kHz 而不是 88.2 kHz —— 否则会丢掉 20–44.1 kHz 那一段。
界面会自动按源速率给出正确的推荐值。

## 已知边界

- 「验证产出」测的是**带内电平**：对音乐是节目电平，对静音探针才是噪声底，它无法区分两者。
- DST 路线走 ffmpeg，**ffmpeg 不能运行 sox 效果**，故该路线下「追加效果」被忽略（程序会提示）。
- 多声道 DSD（>2 声道）通常按声道存成单文件；本程序写单个多声道文件。
- DFF 头不含样本数，时长由文件大小估算；DSF 用头里的精确值。
- 输出标签（ID3v2 等）不会被写入。
