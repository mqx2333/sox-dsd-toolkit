# PCM → DSD 最高质量指令生成器

一个 tkinter GUI：选源文件、选输出位置，程序**实测源文件峰值后自动计算增益**，
并生成一条最高质量的 `sox_ng` 转换指令，可一键复制。

生成指令的目标形态（与你原命令同质量，增益为计算所得）：

```
sox_ng -S --no-clobber "<源>" "<输出>" gain -6 rate -u -b 99 -d 33 5644800 sdm -f sdm-6 -t 8 -n 16 -l 512
```

---

## 运行

```powershell
# 方式一：双击（推荐）
run.bat

# 方式二：命令行
python gui.py
```

无第三方依赖，只需 Python 3.8+ 自带 tkinter。程序会自动寻找 sox_ng：
`%LOCALAPPDATA%\Programs\sox_ng\sox_ng.exe` → `Program Files` → `PATH`，
找不到时在界面上手动指定。

## 增益是怎么算出来的（核心逻辑）

DSD 电平约定：

```
0 dBDSD = 50% 调制 = PCM −6 dBFS        ← 参考电平
SACD 峰值上限 = +3.1 dBDSD ≈ PCM −2.9 dBFS
```

而 `sox` 的 `sdm` 内部把输入乘以 0.5（`src/sdm.c` 的 `x = sample * 0.5`），
所以 **PCM 0 dBFS = 调制器满幅**，远超其稳定区间（±0.71）。也就是说：
峰值顶到 0 dBFS 的母带直接送进调制器，必然过载 —— 而 PCM 域的 `Clip:0`
看不出来，只会在解码回放时表现为带内噪声抬升与空闲音。

因此：

```
gain(dB) = target_peak − measured_peak − safety_margin
```

- `measured_peak`：用 `sox <file> -n stats` 实测（不是猜的）
- `target_peak`：默认 0 dBDSD = **−6 dBFS**
- `safety_margin`：额外余量，默认 0

界面上的「峰值目标 (dBDSD)」就是这么映射的：

| 下拉选项 | 实际目标峰值 | 含义 |
|---|---|---|
| **0.0（默认）** | −6.0 dBFS | 官方 0 dBDSD 参考，推荐 |
| +3.1 | −2.9 dBFS | SACD 峰值上限，最大化 SNR（真峰可能越界） |
| −1.0 / −2.0 / −3.0 | −7.0 / −8.0 / −9.0 dBFS | 更保守，牺牲少量 SNR 换安全性 |

**只衰减、不放大**（除非源本身有大余量，此时才允许小幅提升）。

### 为什么「感觉任何 FLAC 的增益都是 −6 dB」

这是真实现象，不是固定值。对曲库抽样 12 个 FLAC 的实测：

| 文件 | 实测峰值 | 算出增益 |
|---|---|---|
| 流行 / 摇滚（多数） | 0.00 ~ −0.17 dBFS | −6.0 ~ −5.8 |
| Arthur Rubinstein - Nocturne No. 1 | −4.75 dBFS | **−1.2** |
| Arthur Rubinstein - Etude in E minor | −2.36 dBFS | **−3.6** |
| Academy of St. Martin in the Fields | −3.30 dBFS | **−2.7** |

原因：现代母带普遍做**峰值归一化到 0 dBFS**，所以 `gain = −6 − 0 = −6`。
换一首有真实余量的录音（古典、老录音、动态大的作品）增益就会明显不同。

界面上增益输入框旁边会实时显示算式来源，例如
`= 目标 −6.0 dBFS − 实测峰值 −4.75 dBFS`，换文件即刷新。

> 提醒：对峰值已顶格（已削波）的母带，−6 dB **并不能找回动态余量**，
> 只是把音量降到 0 dBDSD 参考电平。它保护调制器不过载，但救不回源削波。

## 重采样是「判断」出来的，不是写死的

程序先读 `sox --i` 拿到真实采样率，再决定：

| 情况 | 生成的指令 |
|---|---|
| 44.1k 家族（44100 / 88200 / 176400…），目标是 5644800 | `rate -u -b 99 -d 33 5644800` —— **不加 `-t`**（整数比，`-t` 无收益） |
| 48k 家族（48000 / 96000…） | 同上但**加 `-t`**（无理数比，需要更高精度），并给出提示 |
| 源速率恰好等于目标速率 | **整个 `rate` 效果省略**（此时它只是空操作） |

48k 家族源还会提示：可考虑改用 48k 家族的 DSD 目标速率（如 6144000）以保持整数比。
目标速率下拉框里的可选项由 `sox_ng --help-format dsf` 实际支持的速率决定，不是猜的。

## 界面上的其他控制

- **噪声整形滤波器**：`clans-*` / `sdm-*` 共 10 个；若所选滤波器与目标速率档不匹配会给出警告
- **trellis order / paths / latency**：范围 3–32 / 4–32 / 100–2048，输入会被自动夹到合法区间
- **重采样极限参数 (-b 99 -d 33)**：默认开，取消勾选即用 `-u` 的默认 95% 通带
- **增益**：默认「自动计算」，输入框实时显示计算值，旁边一行给出算式来源；
  切到「手动」可覆盖，但会提示自动值应该是多少
- **显示进度 -S / 防覆盖 --no-clobber**：默认都开
- **重新测量（可勾选真峰）**：额外做一次 4× 升采样测真峰（ISP），更慢但更准

> 「测量」按钮同时给出：采样率 / 家族 / 位深 / 样本峰值(分声道) / 真峰 / RMS / DC 偏置。
> 源峰值顶到 0 dBFS 时会明确提示母带可能已削波 —— 增益能保护调制器，但救不回源削波。

## 已知边界

- 本程序**只生成指令**，不执行转换（按设计）。指令粘到 PowerShell 里运行。
- 增益基于**样本峰值**，真峰可能更高；已有 −6 dB 余量 + 真峰检测可覆盖，如需更保守把「额外安全余量」设为 0.5–1 dB。
- 真峰检测用 4× 升采样；若源已削波到满刻度，升采样会撞顶，测出的差值会偏小。
- 输出容器的标签（ID3v2/DSF 元数据）不会被 sox 写入，需要另用工具处理。

## ⚠️ 重要：sox_ng 只能写 DSD，不能读回 DSD

本机 sox_ng 14.8.0+git 实测（文件头自称 `Reads: yes`，但实际是坏的）：

```
sox_ng sil_DSD64.dsf -t wav -e signed -b 24 out.wav
→ 解出的 PCM 只有两个取值 ±1.0、各占一半，RMS = 0.00 dBFS
```

它把 1-bit 流当成 **8-bit PCM** 读了，得到的是一条 1.4112 MHz 方波而不是音频。
`.dff` 同样如此（解码时全部样本削波），且 `-e dsd` 这个编码在本构建里不存在。

**后果**：不能用 sox 做「解回 PCM 再验证」这一环。早期文档里
「直接读 .dsf/.dff 再 rate 降采样」的做法在这台机器上无效。

**替代方案（已实测可用）**：用 **ffmpeg**，它的 DSD 解码器正常：

```powershell
ffmpeg -i out.dsf -c:a pcm_s24le -ar 44100 decoded.wav
```

实测：解码静音 DSD64 得峰值 −64.89 dBFS、RMS **−115.70 dBFS**、直流 0 ——
物理上合理（对比 sox 的错误结果：RMS 0.00 dBFS 的方波）。

## 附：DSD 的带内噪声底与等效 PCM 位数

`measure_dsd_noise.py` 实测（静音输入，20 Hz–20 kHz 带内，ffmpeg 解码）：

| 编码 | 调制器 | 带内噪声底 | 等效 PCM 位数 |
|---|---|---|---|
| DSD64 (2.8224 MHz) | clans-8 | −115.7 dB | **18.9**（以 0 dBDSD 参考计 19.9） |
| DSD128 (5.6448 MHz) | clans-7 | −121.3 dB | **19.9**（20.9） |
| DSD256 (11.2896 MHz) | clans-6 | −129.1 dB | **21.2**（22.2） |

等效位数 = (SNR − 1.76) / 6.02，即动态范围与理想 N-bit PCM 满幅正弦相当。
与 NativeDSD 的公开说明一致（DSD64 带内底 ≈ −120 dB、比 20-bit PCM 更安静）。

运行：`python measure_dsd_noise.py`（需 ffmpeg；会编码静音与 997 Hz 探针并测量）
